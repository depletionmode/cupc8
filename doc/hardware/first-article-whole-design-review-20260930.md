# Independent whole-computer first-article engineering critique

Reviewed 2026-09-30 against the actual frozen `build/firstarticle-final-candidate-20260930/source-tree`, current final SPI index, source/functional bridge, acceptance audit, F2 feasibility audit and manufacturing candidate. This is an independent current-model review. It does **not** satisfy the milestone's exact `codex-p`/astra-medium final signoff instruction; it is not David's approval, factory approval or order authorization. No board/source mutations or broad duplicate test run were performed.

## Engineering conclusion

The fitted Main + System + CPU + IO + storage + WiFi + GPU OR eInk computer has substantial real digital integration evidence. There is no newly demonstrated in-target copper fault here that justifies a heavy Main reroute. The current target has conditional terminal SPI evidence; the four preserved early MOSI diagnostics must remain visible, but the separately evaluated sample window is stable in the declared model envelope. Passing native binaries, DC graph and modeled signals does not turn unknown current, regulator transient, package/ground, contact, thermal or ESP timing bounds into guarantees.

Two concrete delivery/operation faults remain in the reviewed candidate: the System bootstrap instructions describe a power path that does not exist, and the supplied eInk image does not match the explicitly selected 7.5-inch physical panel. These can be repaired locally in programming packaging/documentation and selected firmware qualification without changing Main routing. Ordinary all-green release remains blocked by existing red gates and unsatisfied approval requirements. A limited first-article proposal needs an explicit scoped decision; this review grants no waiver.

## Board-by-board critique

### Main

The physical ROM choice is a tape/reel variant of the same SST39VF040-70-4I-NHE, not a smaller-capacity fallback; no software or routing change follows from that packaging suffix. Genuine full512KiB readback and programmer prefix bridge address ROM content provenance. Source/routed runtime equality plus genuine FPGA reset/CDONE/flash mutants are meaningful checks of normal configuration ownership. No reason was found to reopen the established Main route from unrelated sole-WiFi/six-card failures.

Main sustained input copper has a modeled19.519C rise at3.2881A with declared convergence; the margin below20C is small and conditional. MB-108/109 actual resistance/heating, MB-110 contacts, MB-112 loaded thermal soak and MB-113 hot/reset thresholds remain necessary. The reset windows depend on the modeled OPA376 bias allowance; actual hot thresholds and all slot resets must be measured. Cold power cycling after a programmed machine and recovery after a supply sag should be included in existing functional/reset bring-up. This tests a real integration failure mode not covered by nominal boot, without inventing a new threshold.

### CPU

CDONE/CRESET ownership and autonomous boot are supported by combined executed evidence; real core power and far-pin voltage remain unknown under worst workload. Preserve CC-005/006/F2 red, CC-103/104/105 and MB-110. Existing CPU-bus stress waiver does not qualify input reliability and does not extend to slot MISO. Measure receiver overshoot at the actual FPGA pins. First failure beyond a documented accepted exception warrants a local damping/power repair with a counterexample; generic route replacement is unsupported.

### System

System USB is data/sense only, which makes WR-01 an actual bootstrap blocker if instructions are followed literally. The machine supply must also be on. Qualified System ELF/UF2 and physical programming ports are delivered; emulator flashing shows logic but not USB boot ROM enumeration or real SWD/UART timing. YC-007 routed impedance/capacitance failures remain explicitly accepted only for first articles. Test real BOOTSEL+CDC, verify all programmed assets, then cold remove System and repeat boot/keyboard/display/storage/network. No live card removal. The passed System-removal digital fixture is meaningful evidence and need not be rerun solely because review occurred.

### IO

Frozen firmware keeps slot service alive during TinyUSB enumeration and implements TPS2553-1 latched-fault retry. These address real enumeration/starvation and fault behavior. The USB impedance waiver remains. Test the intended boot-protocol HID keyboard, unplug/replug, modifiers and sustained input while other cards are busy. Current actual-C25 transient model passes at647.4mA, but physicalCeff>=1.6uF, boost/switch input voltage and real fault response remain IC-104 obligations. Unknown current loop/response must not be declared bounded by the numerical retry.

### Storage

The delivered firmware runs actual FatFs/SD SPI with worker separation; core-side detect does not concurrently call FatFs, so the initial apparent unmount race is not a demonstrated fault. The examined SD driver uses400kHz identification then12.5MHz transfers, polls card presence/timeouts and has a sync path. Full-target SAVE/LOAD/RUN passes against modeled media. Physical microSD supply peak and real card initialization/format support remain SC-102 and peripheral obligations; an assumed100mA card is not a bound for all microSD products. Specify a tested FAT medium (the chosen FatFs configuration disables exFAT); an arbitrary factory SDXC exFAT card is not demonstrated compatible. Include SAVE/CLOSE then cold-power boot and LOAD from the same real card so volatile image persistence cannot mask a media failure. No unsolicited filesystem rewrite is justified.

### WiFi

Actual physical IDF image offsets are correctly distinguished from QEMU flash; retain this distinction. The local TI stages and output resistor/cap branches have exact final model bindings. Engineering waveform/timing and20us gap are useful scope, but no published process-wide ESP AC bound or guaranteed cascade transfer is established. Measure real short frames, DMA tails, descriptor wrap/rearm and cache-disabled NVS writes at3MHz with held CS; measure the20us service gap. Also qualify sustained TX+SD on3A, attach the exact antenna lead/antenna, check connector mating and external antenna placement, then join the actual AP and fetch via DHCP/DNS/TCP. ESP boot/EN/BOOT/UART/LED boundaries need actual execution. Unknown cap/load/ground/thermal bounds remain red.

### GPU/HDMI

Real PicoDVI firmware emits640x480 and uses the accepted252MHz/1.20V condition. Functional frames do not establish each RP2040's overclock margin, GPIO switching-current rating, TMDS eye or hot operation; modeled83.7C against85C is only1.3C conditional headroom. GC-102 is per used unit; GC-104 rails/current and GC-105 real HPD/DDC/EDID are necessary. Test actual sink/cable and a captured changing image with simultaneous input/SD/network. No claim of HDMI audio/HDCP/universal sink capability is implied by DVI video.

### eInk

WR-02 is independent of PCB geometry. Panel resolution is compiled, not discovered from the write-only header. The recorded7.5-inch selection and default648x480 asset conflict directly. Resolve before claiming the eInk alternative complete. Actual Waveshare5.83-inch glass may lack the fast/partial/4-grey OTP functions used by the default policy; substituting it to fit the currently supplied image is not a safe paper correction. Inspect cable pin order, Driver HATRev2.3, Display ConfigB/0.47ohm and4-line SPI setting; measure panel minimum rail during refresh and BUSY/PWR behavior; test full/partial/grey output and typing refresh latency on the actual chosen glass. Whole-card DC/panel model pass is not a guarantee of the external HAT LDO/dropout/translator/cable waveform.
